GitHub 使用指南

GitHub 是全球最大的代码托管与协作平台。它不只是一个“放代码的地方”，更是开源协作、持续集成、项目管理的一整套基础设施。本文从零开始，把上手 GitHub 需要知道的东西串成一条线：账号配置 → 核心概念 → 常用命令 → 协作流程 → 仓库工程化 → 安全实践。

一、先搞清楚 Git 和 GitHub 的关系

Git GitHub
是什么 分布式版本控制工具，装在你电脑上 基于 Git 的托管平台，跑在云上
管什么 本地代码的历史版本 远程仓库、协作、CI/CD、Issues
没有对方能用吗 能，纯本地也能版本管理 不能，底层依赖 Git 协议

一句话：Git 是工具，GitHub 是服务。学会 Git 的命令，换到 GitLab、Gitee、Bitbucket 都是同一套。

二、注册之后先做这三件事

1. 开启两步验证（2FA）

GitHub 从 2023 年起强制要求贡献者开启 2FA。路径：Settings → Password and authentication → Two-factor authentication。推荐用 TOTP（手机验证器 App），比短信可靠。

2. 配置 SSH 密钥（推荐）

用 SSH 比每次输 token 舒服得多。

把输出的那一整行粘贴到 GitHub → Settings → SSH and GPG keys → New SSH key。

3. 配置提交身份

提交记录里的作者信息来自 Git 配置，不是 GitHub 账号，配错了贡献图不会点亮：

如果不想暴露真实邮箱，可以在 GitHub 设置里开启 Keep my email addresses private，用 ID+username@users.noreply.github.com 作为提交邮箱。

4. HTTPS 方式：用 Personal Access Token

GitHub 早已不支持密码推送。HTTPS 方式需要 token：

Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token

  • Repository access：选要授权的仓库
  • Permissions：至少给 Contents: Read and write；要用 Actions / Pages 还要单独授权
  • 生成后只显示一次，立刻保存到密码管理器

三、必须掌握的七个概念

概念 说明 类比
Repository 仓库，一个项目 一个文件夹
Commit 一次提交，带 hash 和说明 一次存档
Branch 分支，平行开发线 平行世界
Pull Request 请求把分支合并进主分支 提案 + 评审
Issue 问题/任务/讨论 工单
Fork 把别人仓库复制到自己名下 拷贝一份
Star / Watch 收藏 / 订阅通知 点赞 / 关注

还有几个高频词：clone（下载到本地）、remote（远程仓库地址）、merge（合并）、rebase（变基）、tag / release（打标签、发版本）、Actions（自动化流水线）、Pages（静态站点托管）。

铁律：已经 push 到公共分支的提交，不要用 reset --hard 改写历史，用 revert。改写历史会让所有协作者的分支错乱。

六、让仓库变得专业

一个让人愿意用的仓库，通常长这样：

README 的最小合格线：一句话说明 + 安装命令 + 一个可运行示例 + 截图或 GIF。

.gitignore 直接用 github/gitignore 里对应语言的模板，不要自己从零写。

许可证快速选择：

  • 想让人随便用（含商用）：MIT / Apache-2.0
  • 衍生作品必须开源：GPL-3.0
  • 只是放作品不允许商用：CC BY-NC 4.0

在 .github/workflows/ci.yml 放一个文件，就能让 GitHub 免费帮你跑测试、构建、部署：

几个要点：

  • on 决定触发时机，jobs.steps 是顺序执行的步骤
  • 公共仓库的 Actions 免费额度很宽裕，私有仓库每月有赠送分钟数

八、GitHub Pages：免费托管静态站点

三种发布方式：

方式 适用场景 配置位置
Deploy from a branch 纯静态产物（Hexo / Hugo / Vite 构建结果） Settings → Pages → 选分支和目录
GitHub Actions 需要构建步骤，想控制构建流程 用 actions/deploy-pages 写 workflow
自定义域名 有自己域名 仓库加 CNAME 文件 + DNS 解析

用户主页仓库要命名为 <用户名>.github.io，访问地址就是 https://<用户名>.github.io/；其他仓库则是 https://<用户名>.github.io/<仓库名>/，此时构建配置里的 base / root 要相应调整。

九、安全：这几件事千万别做

  1. 不要把 token、密钥、密码提交进仓库。哪怕删掉，历史里依然存在，爬虫几分钟就能扫到。
  2. 用 .env + .gitignore，配置走环境变量或 Secrets。

十、常见问题

push 被拒绝：non-fast-forward
远程有你本地没有的提交。先 git pull --rebase，解决冲突后再 push。不要直接 --force 到公共分支。

Permission denied (publickey)
SSH 密钥没配好。先 ssh -T git@github.com 测试，检查公钥是否已添加到 GitHub。

国内访问慢或连不上
给 Git 配置代理（端口改成你本地代理的端口）：

仓库太大，clone 很慢
用浅克隆只取最近一次提交：git clone --depth 1 <url>。

误提交了大文件
用 Git LFS 管理二进制文件：git lfs install && git lfs track "*.psd"；已经进历史的大文件要用 git filter-repo 清理。

十一、一页速查

GitHub 的学习曲线主要不在命令，而在协作习惯：小步提交、写清楚说明、分支保护、PR 评审、CI 兜底。把这几点养成习惯，比背一百条命令有用。
